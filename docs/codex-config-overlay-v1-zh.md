# Codex 公共配置 v1 决策稿

> 状态：v1 规则已确认并已在当前代码中实现。本文约束当前简化版，不引入完整版本的配置基准与冲突决策流程；旧供应商快照转换仍是独立的一次性数据操作。

## 目标

- Codex 只有一份全局公共配置，存入现有 `common_config_codex` 设置项。
- 每个供应商只保存自己的私有配置，不再保存公共配置快照。
- 生效配置由公共配置与当前供应商私有配置合成，私有值优先。
- 私有配置可新增字段、覆盖公共字段，也可显式屏蔽公共字段。
- 发现生效文件被外部修改后，自动把变更归并到公共配置或当前供应商私有配置，不要求用户选择处理策略。
- v1 不保存全局“最近生效配置”或等价快照。

## 配置模型

用 `C` 表示全局公共配置，`Pᵢ` 表示供应商 `i` 的稀疏私有配置，`Eᵢ` 表示最终生效配置：

```text
Eᵢ = merge(C, Pᵢ)
```

公共配置和私有配置都按 TOML 语义解析，不按原始文本比较。TOML 表递归合并；数组作为一个整体值处理。

对公共字段，供应商私有配置有三种状态：

| 私有状态 | 生效结果 |
| --- | --- |
| 未记录 | 继承公共值 |
| 设置为值 | 使用供应商私有值 |
| 显式删除 | 生效配置中不输出该字段，即使公共配置中存在 |

删除标记必须与“未设置私有值”分开保存。空字符串、`false`、`0`、空数组都是合法私有值，不代表删除。

供应商身份、认证、路由、模型等现有供应商字段仍由供应商行负责。字段归属沿用 Codex 现有关键字段定义；公共配置不得覆盖这些供应商字段。

## 外部磁盘修改

不记录额外的最近生效基准。同步时读取当前公共配置 `C`、当前生效供应商的私有配置 `Pᵢ`，计算期望配置 `Eᵢ`，再与磁盘实际配置 `A` 做语义差异比较：

```text
Eᵢ = merge(C, Pᵢ)
变化 = diff(Eᵢ, A)
```

逐字段处理差异：

1. 如果字段已有私有覆盖，且磁盘值与公共值相同，删除私有覆盖，恢复继承。
2. 如果字段已有私有覆盖，且磁盘值不同于公共值，把磁盘值写入当前供应商私有配置。
3. 如果字段没有私有覆盖，且属于公共字段，把磁盘值写入全局公共配置。
4. 如果磁盘删除了一个已被私有覆盖的公共字段，记录私有删除标记；如果该字段没有私有覆盖，则从全局公共配置删除。
5. 供应商专属字段只更新当前供应商；代理注入的本地 URL、占位凭据等派生值不得回写供应商上游配置。

例如：公共值为 `1`、当前供应商私有值为 `2`，期望值是 `2`。磁盘变成 `3` 时私有值更新为 `3`；磁盘变回 `1` 时删除私有覆盖，后续继续继承公共值。

这套规则以磁盘实际值作为检测到的外部修改结果，不弹出“保留哪边”的策略选择。应用内保存仍须使用现有写入引擎的并发保护，避免写入期间覆盖刚发生的磁盘变化。

### 基准缺失的明确限制

不保留最近生效基准意味着：当磁盘值与当前 `merge(C, Pᵢ)` 不同，系统只能按上述规则把磁盘值视作外部修改，无法判断磁盘是否只是尚未应用的新公共配置的旧副本。因此 v1 必须让公共配置更新与生效文件写入处于同一受保护操作中，并在存在未完成写入时先恢复该操作，再执行外部归并。若无法确认当前供应商或操作状态，不做自动归并。

## 检测触发与模式边界

- Codex live 文件的外部修改会在切换供应商、保存供应商配置或保存公共配置时，与当前供应商的期望配置比较并归并；写入引擎仍会在发布前重读并校验文件 hash。
- 当前没有 Codex 配置文件后台 watcher，也没有启动时把 Codex live 配置同步回供应商的逻辑；因此归并发生在上述操作触发时，不是实时后台监听。
- Stack 同时组合多个供应商，无法唯一归属客户端级配置变更；v1 在 Stack 生效时跳过自动归并。
- 本地路由按客户端配置的主路由供应商作为当前供应商。请求级故障转移不改变私有配置归属。

## 旧数据处理

现有供应商行可能保存旧公共配置快照。切换到 v1 前，需进行一次性数据转换：

1. 备份数据库并预览 `common_config_codex` 与所有 Codex 供应商配置。
2. 依照已确认的公共字段规则整理公共配置；保留当前供应商的供应商专属字段。
3. 从供应商行移除公共配置快照，只保留供应商私有字段及必要的显式覆盖/删除信息。
4. 校验转换后当前生效配置与转换前预期一致。
5. 转换通过后不保留启动期迁移逻辑；后续运行只使用新配置模型。

数据转换是独立的一次性数据库操作。不得在本方案实现期间擅自批量改写日常用户数据库；应先预览、备份并确认具体数据范围。

## v1 不做

- 不保存最近生效配置快照，不做完整三方合并。
- 不提供冲突策略选择弹窗；已识别的外部差异按本文件规则自动归并。
- 不实现 Codex 后台文件 watcher。
- 不在 Stack 下猜测外部改动应属于哪个成员。
- 不把代理本地投影值写回供应商数据。

## 验收场景

1. 公共字段 `x=1`，甲没有私有值、乙私有值为 `2`：甲生效为 `1`，乙生效为 `2`。
2. 公共字段 `x=1`、私有字段为 `2`，外部改为 `3`：当前供应商私有值变为 `3`，公共值和其他供应商不变。
3. 公共字段 `x=1`、私有字段为 `2`，外部改回 `1`：清除该供应商私有覆盖，恢复继承。
4. 公共字段没有私有覆盖，外部把它改为 `3`：更新唯一的公共配置，其他继承该字段的供应商也生效为 `3`。
5. 私有字段被外部删除：公共字段存在时记为私有删除；公共字段不存在时从私有配置移除。
6. TOML 注释、空白或键顺序变化不产生配置归并。
7. 非法 TOML、Stack 归属不明、写入未完成或并发 hash 检查失败时，不更新配置层数据。
8. 代理模式下的本地地址、代理凭据占位符不会进入供应商私有配置。
9. 旧供应商快照转换前有备份，转换结果验证通过后不需要每次启动再迁移。
