# Codex 公共配置与供应商覆盖方案（完整方案草案）

> 状态：已由简化版决策稿取代。本文保留完整方案供未来扩展参考；当前 v1 以 [Codex 公共配置 v1 决策稿](codex-config-overlay-v1-zh.md) 为准。

## 背景与问题

Codex 配置中，供应商身份、认证和连接信息天然属于供应商；其他运行时字段虽然通常是公共设置，但不一定对每个供应商都适用。只保存一份公共配置会让所有供应商共享同一组值；把完整配置复制到每个供应商则会形成重复快照，公共字段后续变化难以同步，也无法区分“继承公共值”和“供应商主动设置了相同值”。

目标是让公共配置和供应商配置分别持久化，启用时生成一份 Codex 实际读取的配置，同时允许用户在应用外编辑该生效配置，并尽量把编辑结果归并回正确的配置层。

## 目标与边界

### 目标

- 公共配置只有一个来源，适用于所有 Codex 供应商。
- 每个供应商只保存相对公共配置的差异，不复制整份公共配置。
- 供应商覆盖支持设值、继承公共值和屏蔽公共值。
- 应用目录中的外部编辑可被识别，并在没有歧义时归并到当前供应商覆盖。
- 应用内修改与外部修改并发触及同一字段时，不静默丢弃任何一方。
- 配置解析、写入或迁移失败时保留原文件和原有数据。

### 不在本方案内

- 不改变各供应商自身的身份、凭证、端点等供应商专属字段的所有权；这些字段仍由现有供应商资料负责。
- 不通过外部编辑生效文件来隐式修改公共配置。公共配置应通过明确的公共配置编辑入口修改；未来可以另加“设为公共值”操作。
- 不自动推断旧供应商完整配置快照之间的差异就是用户有意设置的覆盖。
- 不在无法确定供应商上下文时自动归并外部修改，例如 Codex Stack 同时组合多个供应商的场景。

## 配置模型

以下用 `C` 表示公共配置，`Pᵢ` 表示供应商 `i` 的私有覆盖，`Eᵢ` 表示该供应商最终生效的配置。

```text
Eᵢ = 合成(供应商专属字段ᵢ, merge(C, Pᵢ))
```

公共字段与供应商专属字段必须有明确的字段所有权定义，避免同一个字段同时由公共配置、供应商资料和覆盖层写入。只有列入公共/覆盖配置管理范围的字段参与 `merge`；其他由 Codex 或用户维护的字段按现有规则保留，不因重建配置而丢失。

### 供应商覆盖的三种状态

对任一可覆盖字段，供应商配置采用稀疏操作，而不是“字段缺省就等于空值”：

| 私有状态 | 含义 | 生效结果 |
| --- | --- | --- |
| 未记录 | 继承 | 使用公共配置中的值；公共也没有时则不输出该字段 |
| `Set(value)` | 覆盖 | 使用供应商私有值，包括空字符串、`false`、`0` 或空数组等合法值 |
| `Delete` | 屏蔽 | 即使公共配置有该字段，生效配置中也不输出它 |

`Delete` 是显式删除标记，不能与“未记录/继承”混为一谈。删除一个私有覆盖、恢复继承，与屏蔽一个公共字段是两个不同操作。若配置格式支持显式空值，空值也是 `Set(value)`，不是 `Delete`。

### 合并粒度

- 默认按 TOML 表递归合并，叶子值按字段处理。
- 数组按整体值处理，不自动按下标合并，避免顺序或长度变化造成错误拼接。
- 需要整体替换的表可以在字段定义中指定为原子值；需要逐项继承的表则允许子字段独立覆盖。
- 删除父级表会屏蔽该表下的公共子项；存储时应规范化父子路径，避免互相矛盾的覆盖操作。
- 比较采用解析后的语义值，不比较空格、注释、键顺序等 TOML 文本格式差异。

## 外部修改归并

单靠读取当前文件无法还原用户意图。例如公共值为 `1`、私有值为 `2` 时，磁盘值变成 `3` 通常表示把当前供应商覆盖改成 `3`；磁盘值变回 `1` 通常表示删除私有覆盖并恢复继承。但如果应用内也同时修改了同一字段，不能仅凭最终值判断应覆盖哪一方。

因此每个配置目标需要记录最近一次成功应用的、已规范化的受管配置快照 `L`，以及生成该快照的供应商 ID 和配置模式。检测到变化时读取磁盘配置 `A`，并按当前 `C`、`Pᵢ` 计算应用期望配置 `Eᵢ`。三者构成三方比较：

```text
L：上次成功应用的共同基准
A：现在磁盘上的配置
Eᵢ：按当前公共配置和供应商覆盖计算出的期望配置
```

对每个受管字段分别处理：

| 相对 `L` 的变化 | 处理 |
| --- | --- |
| `A` 未变，`Eᵢ` 已变 | 属于应用内修改，将 `Eᵢ` 写入磁盘 |
| `A` 已变，`Eᵢ` 未变 | 属于外部修改，按下文规则更新当前供应商覆盖 |
| 两边都变且语义结果相同 | 视为已收敛，保留配置模型并更新成功应用快照 |
| 两边都变且结果不同 | 对已检测到的外部改动采用磁盘实际值，按下文规则更新当前供应商覆盖，不要求用户选择 |
| 两边都未变 | 无需处理 |

`L` 的作用是区分“应用内配置刚变化、目标文件还没写入”和“目标文件确实被外部改动”，不是要求用户解决值冲突。对检测到外部变化的字段，采用明确的“磁盘实际值优先”策略，即使 `Eᵢ` 也在同一字段发生变化，也按 `A` 更新供应商私有层。

外部修改按以下规则映射到**当前活动供应商**的私有层：

1. 外部值与当前公共值相同（包括双方都不存在）时，移除该字段的私有操作，使其继承公共配置。
2. 外部字段存在且不等于公共值时，保存为 `Set(外部值)`。
3. 外部字段不存在而公共字段存在时，保存为 `Delete`，防止公共值重新出现。
4. 归并后重新计算 `Eᵢ`，使它与外部配置的受管部分一致，然后更新 `L`。

示例：

| 公共值 `C` | 私有值 `P` | 上次应用 `L` | 外部值 `A` | 归并结果 |
| --- | --- | --- | --- | --- |
| `1` | `2` | `2` | `3` | 私有值更新为 `3` |
| `1` | `2` | `2` | `1` | 删除私有覆盖，继承公共值 `1` |
| `1` | 继承 | `1` | `3` | 当前供应商新增私有值 `3`，不修改公共配置 |
| `1` | `2` | `2` | 不存在 | 私有状态改为 `Delete` |

例如 `L=2`、应用内已将期望改为 `4`、磁盘被外部改为 `3`。由于 `A` 相对 `L` 确实发生了变化，按本方案的优先级将 `3` 归并到当前供应商私有层；不弹出“采用外部值/保留应用配置”的选择框。归并后可以向用户显示同步结果，但通知不阻塞配置生效。

## 本地路由模式

路由模式下仍然只有一份 Codex 客户端配置，但有明确的当前主路由供应商。对主路由供应商 `i`，先计算逻辑配置，再应用本地路由投影：

```text
Dᵢ = 合成(供应商专属字段ᵢ, merge(C, Pᵢ))
Rᵢ = 路由投影(Dᵢ)
```

- 主路由供应商从 `i` 切换到 `j` 时，应用 `Rⱼ`，不是继续复用 `Rᵢ`；每个供应商仍有独立的期望配置 `Eᵢ`。
- `Rᵢ` 中由路由层生成的本地代理地址、代理认证占位符和路由选择字段属于派生/路由托管字段，不参与公共值与私有值的比较，也不能被回写成供应商上游地址或凭证。
- 路由期间检测到外部改动时，将普通受管字段的改动归属到**生成当前客户端文件投影的供应商**，按前述“实际值优先”规则更新其 `Pᵢ`；路由托管字段则保持由路由投影负责。
- `L` 必须绑定“客户端文件投影供应商”，不能只读取当前代理上游指针。自动故障转移会在请求运行时切换代理上游，但不会重写 Codex 客户端配置；因此故障转移到供应商 `j` 不会把 `Pᵢ` 的客户端配置改成 `Pⱼ`，也不能改变 `L` 所记录的投影归属。
- 手动切换主路由或退出路由前，先用旧的 `L` 和投影供应商归并尚未处理的外部改动，再生成并应用新目标的期望配置。

### 请求级故障转移的兼容性

每个供应商可以有自己的期望配置 `Eᵢ`，但这不表示请求故障转移时能临时把 Codex 客户端配置从 `Eᵢ` 换成 `Eⱼ`。Codex 已经按当前加载的配置构造了请求；故障转移只发生在本地代理选择上游之后，不会重启 Codex 或重写它的配置。

因此要区分两类差异：

| 差异类型 | 处理方式 |
| --- | --- |
| 上游地址、凭证，以及代理已支持按供应商处理的协议/模型映射 | 保存在各供应商资料中，由代理为所选上游使用；这类差异本身不要求改写 Codex 客户端配置 |
| 必须由 Codex 客户端在发请求前采用的设置，且代理无法在请求级转换 | 作为该供应商的客户端配置要求；只有要求兼容的供应商才能互相自动故障转移 |

建议为故障转移定义“客户端请求契约兼容性”，而不是简单比较两份完整配置是否相同：只有代理适配器明确支持的差异才视为可转换；其余客户端侧关键要求不兼容时，不允许加入同一自动故障转移组，并提示用户只能手动切换主路由。手动切换到供应商 `j` 时，CC Switch 再应用 `Eⱼ` 的路由投影。不能静默地拿 `Eᵢ` 去尝试一个明确要求 `Eⱼ` 的上游。

如果产品希望不兼容供应商也能自动互相故障转移，就必须扩展代理：在每次上游选择后按该供应商要求重写/转换请求，并验证响应转换及模型、工具、推理参数等语义。仅有“每供应商一个配置”这层数据模型还不够。

## Codex Stack

Stack 会同时向 Codex 发布多个供应商的模型。Stack 与本地路由是不同模式，Stack 下的外部修改可能针对客户端公共设置，也可能针对多个成员中的某个模型/供应商，不能一概归入单个成员的 `Pᵢ`。

- 归属明确到某个供应商模型条目的字段，可以按该条目的所有权规则处理。
- 客户端级或归属不明的外部改动，不自动写入任一成员覆盖，也不扩散为公共配置；保留并提示需要明确作用范围。
- 应用内编辑公共配置或成员覆盖时，必须提供明确目标。

## 文件监控、写入与失败处理

- 文件监控事件应去抖，并以重新读取后的文件内容为准；监控事件本身不视为一次完整编辑。
- 自身写入产生的事件通过内容哈希/修订号识别，避免把应用写入误当成外部修改。
- 读改写串行化；写入前重新读取并比较文件修订，若目标文件在比较后已变化则中止本次写入，重新读取并按外部修改规则归并后重试。
- 使用临时文件和原子替换，尽量避免崩溃留下半份 TOML。
- 先解析并验证完整文件；语法错误或受管值类型不合法时不自动修复、不覆盖原文件，提示用户修复后重试。
- 只有确认文件写入成功后才推进 `L`。若进程可能在文件写入与状态持久化之间崩溃，应有可恢复的待应用记录；启动时校验磁盘哈希后完成或回滚该记录。
- 外部改动涉及非受管字段时，应保留原值；写入受管字段不得重建并丢弃未知字段。

跨进程文件编辑无法提供真正的原子比较交换。修订检查能发现大多数竞争，但不能消除检查与替换之间极短的竞态；实现时应使用尽可能窄的读改写窗口，并在后续检查中再次检测内容漂移。

## 旧数据迁移

当前供应商记录中可能存在完整配置快照，且不同快照不一定代表有意的供应商差异。因此不能仅靠“和某个公共配置做 diff”自动生成私有覆盖，否则历史残留、默认值和偶然差异可能变成长期覆盖。

建议迁移步骤：

1. 明确选择一份可信来源作为初始公共配置；不得静默选择任意供应商快照作为公共基线。
2. 保留迁移前数据库记录和目标配置文件的可恢复备份。
3. 默认将旧快照差异列为迁移预览，不自动导入为私有覆盖。
4. 用户确认后，可逐供应商采纳预览出的差异；未确认的字段按选定策略处理，不能静默丢弃。
5. 迁移完成后校验每个供应商的最终有效配置与迁移前可见配置差异，并提供撤销/恢复路径。

如果不能可靠确定现有公共配置的来源，迁移应停止在预览和确认阶段，不应为了完成自动迁移而猜测。

## 界面建议

- 公共配置有独立编辑入口，与供应商表单分开。
- 供应商详情按字段显示“继承公共值”“供应商覆盖”“屏蔽公共值”，并提供恢复继承操作。
- 对公共字段不存在、私有覆盖新增字段、以及私有删除标记使用不同状态展示。
- 保存前可查看所选供应商的最终生效配置及相对公共配置的差异。
- 外部变更自动归并后可展示哪些字段更新了私有覆盖、哪些字段恢复了公共继承；该提示不要求用户确认。
- Stack 上下文不明时说明不能自动归属，并允许用户选择作用范围后再处理。

## 验收场景

1. 公共字段 `x=1`，供应商甲继承、供应商乙覆盖为 `2`：甲生效为 `1`，乙生效为 `2`。
2. 公共配置新增字段 `y=3`：所有继承该字段的供应商均生效为 `3`，显式覆盖或删除的供应商除外。
3. 供应商对公共字段设置 `Delete`：该字段从生效配置中消失；恢复继承后重新出现。
4. 私有值为 `2`，外部将磁盘值改为 `3`：无并发冲突时只更新当前供应商覆盖，其他供应商和公共配置不变。
5. 私有值为 `2`，外部将磁盘值改回公共值 `1`：删除私有覆盖，后续公共值变化仍能被继承。
6. 字段此前继承公共值 `1`，外部改为 `3`：为当前供应商建立覆盖，不静默改动公共配置。
7. 应用内与外部同时修改同一字段为不同值：确认磁盘字段相对 `L` 发生外部变化后，磁盘实际值自动写入当前供应商私有层；不弹出值选择确认框。
8. 应用内与外部修改不同字段：两处改动都保留并合并。
9. TOML 仅有注释、空格或键顺序变化：不产生语义变更或供应商覆盖。
10. 非法 TOML、文件并发变化或写入失败：保留原文件和原配置状态，不推进成功应用快照。
11. Stack 活动时检测到外部受管字段变化：不自动选择某个供应商作为归属对象。
12. 迁移旧供应商快照：未确认的差异不会自动变成私有覆盖，且可恢复迁移前数据。
13. 路由主供应商从甲切换到乙：客户端文件先归并甲名下的外部改动，再应用乙的 `E乙` 路由投影；本地代理地址和占位凭证不进入乙的私有覆盖。
14. 路由请求故障转移到备用供应商乙：不重写 Codex 客户端文件，不把投影快照的归属从主路由供应商甲改成乙。
15. 甲乙只有上游地址或凭证不同、且代理能分别处理：故障转移使用各自的供应商资料，不要求切换客户端期望配置。
16. 甲乙需要不同且代理无法转换的客户端请求契约：两者不能进入同一自动故障转移组；手动切换乙后应用 `E乙`。

## 待确认决策

实施前建议先确认以下产品语义：

1. 外部编辑始终归属当前单一活动供应商；如需改公共值，必须使用公共配置入口或显式“设为公共值”操作。
2. 对已确认的外部字段改动，以磁盘实际值为准自动归并；`L` 只用于区分外部编辑与应用自身尚未写入的修改。
3. 本地路由按生成客户端文件投影的主路由供应商归并外部修改；请求级故障转移不改变该归属。
4. 请求级故障转移只允许在客户端请求契约兼容的供应商之间进行；不兼容差异必须由代理适配，不能靠切换静态客户端配置解决。
5. Codex Stack 中客户端级或归属不明的外部编辑不自动归入成员覆盖。
6. 旧供应商快照只生成迁移预览，不自动按差异批量转换。
7. 数组整体覆盖、表递归覆盖作为默认合并规则；特殊字段再单独声明合并粒度。

以上决策确认后，再拆分数据结构、迁移、文件监控、同步状态展示与异常处理；在确认前不建议直接改动现有配置逻辑或用户配置数据。
